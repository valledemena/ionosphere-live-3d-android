# R4.6.6 - Higiene de CI: el run publica cuantos tests corrieron

Fecha: 2026-11-19. Slice R4.6.6 de R4.6, previo GO escrito de David. Un slice =
un PR.

## 1. Problema, medido

El job `unitTest` del CI ejecuta `./gradlew --no-daemon testDebugUnitTest` y su
log no imprime cuantos tests corrieron. Consecuencia: "324 tests / 0 fallos / 51
ficheros" era **evidencia local** y el run no la refrendaba. Cualquier acta que
cite esa cifra depende de que el implementador la haya medido, no de que CI la
publique.

Restriccion de alcance: `.github/**` no se toca. El resumen tiene que salir del
propio Gradle, que ademas asi vale igual en local.

## 2. Que cambia

- `gradle/tests-summary.gradle.kts` (nuevo): tras cada tarea `Test`, lee los XML
  que la tarea acaba de escribir (`reports.junitXml.outputLocation`, con respaldo
  en `build/test-results/<tarea>`), suma `tests`, `failures`, `errors` y
  `skipped` de cada `testsuite` y escribe **una** linea estable:

  ```
  RESUMEN-TESTS tarea=testDebugUnitTest ficheros=51 tests=324 fallos=0 errores=0 omitidos=0
  ```

- `app/build.gradle.kts`: aplica el script con
  `apply(from = rootProject.file("gradle/tests-summary.gradle.kts"))`.

La linea es ASCII, `clave=valor`, sin fecha ni rutas absolutas: se puede citar en
un acta y comparar entre runs.

**Guarda**: si la tarea termina sin ningun `TEST-*.xml`, el resumen **falla** el
build con `RESUMEN-TESTS: sin resultados en <dir>; no se puede afirmar el numero
de tests de <tarea>`. Un cero silencioso seria peor que la ausencia actual: se
leeria como "corrieron cero tests y todo bien".

## 3. Evidencia (medida en este worktree, `db5e7cb` + este cambio)

1. Run completo:
   `gradlew --no-daemon :app:testDebugUnitTest --rerun-tasks` ->
   `BUILD SUCCESSFUL in 2m 7s` y
   `RESUMEN-TESTS tarea=testDebugUnitTest ficheros=51 tests=324 fallos=0 errores=0 omitidos=0`.
2. Cruce contra los XML del mismo run, contados aparte: **51 ficheros / 324
   tests / 0 fallos / 0 errores / 0 omitidos**. Coinciden.
3. **Falsificacion** (que la linea no sea un numero fijo): mismo comando con
   `--tests "com.valledemena.ionosphere.ui.hud.HudSliceTest"` ->
   `RESUMEN-TESTS tarea=testDebugUnitTest ficheros=1 tests=4 fallos=0 errores=0 omitidos=0`,
   y el XML de ese run es exactamente
   `TEST-com.valledemena.ionosphere.ui.hud.HudSliceTest.xml` con `tests=4`. La
   linea sigue al resultado real.

## 4. Limites declarados

- **Sin costura JVM**: la logica vive en un script de Gradle, no en `app/`, para
  no meter codigo de CI en el APK. No hay test JUnit ni mutante sobre ella; la
  falsificacion es empirica (punto 3) y el parseo es de tres lineas.
- **Guarda probada por lectura**, no falsificada: inducir "tarea Test sin XML"
  exige romper el build de forma artificial. Queda anotado como NO PROBADO.
- **No cambia** que hace el CI: mismos jobs, mismos comandos, mismas 3/3. Solo
  anade una linea al log.
- **No cambia** `data/**`, `.github/**` ni el checker congelado
  (`343c8104de65cb13086f22436083561ad1c32473`).

## 5. Criterio de salida

- CI 3/3 en el PR y, en el run de `main` tras el merge, la linea
  `RESUMEN-TESTS` visible en el job `unitTest` con los contadores reales.
- Desde ese momento, la cifra de tests deja de ser solo local: la publica CI.
